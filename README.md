# Материалы занятия CI/CD 

## Содержимое

- `STUDENT_TASK.md` — задание и критерии.
- `demo/` — исходный проект с работающими тестами и CI.
- `workflow_templates/ci.yml.txt` — CI для копирования через веб-интерфейс.
- `workflow_templates/ci-cd.yml.txt` — полная замена CI для показа публикации GitHub Pages.
- `diagrams/` — четыре схемы PNG для экрана и доски.
- `offline/` — журналы реальных локальных прогонов и исправный/сломанный сайт.

## Быстрый запуск локально

Из папки `demo` в терминале с Python 3.12 или новее:

```bash
python -m unittest discover -s tests -v
python build.py
```

В Windows команда может называться `py -3`, в Linux/macOS — `python3`. В GitHub Actions используйте `python`, как в готовом YAML. Дополнительные пакеты не нужны. Откройте `dist/index.html`; при желании запустите `python -m http.server 8000 --directory dist` и откройте http://localhost:8000 . Остановить сервер — Ctrl+C.

## Настройка GitHub

Для учебной практики создайте отдельный публичный репозиторий с README и веткой `main`. Загрузите содержимое `demo` в корень, **включая** `.github/workflows/ci.yml`. Через веб-интерфейс надёжнее отдельно создать workflow полным путём и вставить содержимое шаблона. Не кладите проект в дополнительную папку `demo` внутри репозитория.

Для демонстрации CD выберите Settings → Pages → Source → GitHub Actions и **замените содержимое существующего** `.github/workflows/ci.yml` файлом `workflow_templates/ci-cd.yml.txt`. Не создавайте второй одновременно работающий workflow. Публикация делается только из `main` после успешной проверки и сборки; PR не публикуются.

CD в этом примере обновляет публичный учебный сайт. Не размещайте на странице персональные данные. После смены текста найдите URL в шаге Deploy site и откройте опубликованную версию. Ссылка обычно имеет вид https://ИМЯ.github.io/РЕПОЗИТОРИЙ/ , но используйте фактический адрес из запуска.

## Минимальный словарь
•	Pipeline — конвейер обработки изменения. Здесь: проверка, подготовка файлов и при включённом CD публикация.
•	Workflow — файл сценария GitHub Actions. Один файл может содержать несколько jobs.
•	Event — событие запуска. Push отправляет изменения; pull request предлагает их объединить; workflow_dispatch разрешает ручной запуск.
•	Job — группа шагов, выполняемая на runner. Разные jobs могут работать независимо; порядок между ними задают зависимостями.
•	Step — отдельный шаг внутри job. Обычные шаги выполняются последовательно.
•	Action — готовая переиспользуемая операция, например получение репозитория.
•	Artifact — сохранённый результат запуска: в примере комплект файлов сайта.
•	Log — журнал, в котором видны выполненные команды и их вывод.
•	Deploy — размещение подготовленной версии в целевой среде.
